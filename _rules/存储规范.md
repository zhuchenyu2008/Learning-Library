# Learning-Library 仓库存储规范

## 一、适用范围

本规范用于 `Learning-Library` 仓库中的所有学习资料，包括但不限于：

- 课堂录音转文字稿
- 课堂笔记
- 要背的东西
- 课后整理资料
- 作业错题
- 老师上课时书写和使用的资料
- 课堂练习
- 试卷与答案
- 老师补充资料
- 其他与课程相关的资料

本规范主要规定文件命名、目录组织、归档方式、文件保护、信息关联和仓库允许保存的文件类型。

**不规定具体笔记应该怎么写。**

---

# 二、核心原则

## 1. 每个文件必须可以独立识别

任何文件即使脱离原文件夹，也必须仅通过文件名判断出：

1. 科目
2. 第几次课
3. 资料类型
4. 课程内容
5. 日期
6. 星期

禁止：

```text
课堂笔记.md
课件.md
录音转写.txt
错题.md
```

应使用：

```text
政治1_课堂笔记_必修一第1-2课_2026-09-08_周二.md
```

## 2. 文件名统一格式

```text
科目+课次_资料类型_课程内容_YYYY-MM-DD_周X.扩展名
```

例如：

```text
政治1_课堂笔记_必修一第1-2课_2026-09-08_周二.md
政治1_错题_必修一第1-2课_2026-09-08_周二.md
英语3_课后整理_阅读理解细节题_2026-09-12_周六.md
```

日期统一按照**北京时间**记录。

---

# 三、文件名字段

## 1. 科目 + 课次

```text
政治1
政治2
英语1
数学1
语文1
```

每个科目独立计算课次，按照实际上课顺序递增。

## 2. 资料类型

常用类型包括：

```text
课堂录音转文字稿
课堂笔记
要背的东西
课后整理
错题
老师课件转写
老师板书转写
老师补充资料
课堂练习
课堂试卷
课堂答案
教材资料
参考资料
其他资料
```

实际资料不属于上述类型时，可以根据内容新增清晰名称。

## 3. 课程内容

例如：

```text
必修一第1-2课
必修一第3课
函数的概念
集合
阅读理解细节题
生产力与生产关系
```

应以实际课程内容为准，不得为了文件名完整而猜测。

## 4. 日期与星期

格式：

```text
2026-09-08_周二
```

日期与星期必须核对一致。

---

# 四、分隔符

主字段使用 `_` 分隔。

```text
政治1_课堂笔记_必修一第1-2课_2026-09-08_周二.md
```

`-` 可用于日期或内容内部范围：

```text
2026-09-08
第1-2课
```

---

# 五、目录组织

仓库按科目组织：

```text
Learning-Library/
├── README.md
├── _rules/
│   ├── 存储规范.md
│   └── 错题存储规范.md
├── 政治/
├── 英语/
├── 数学/
├── 语文/
└── 其他科目/
```

科目内部：

```text
政治/
└── 2026-首考/
    ├── 课堂/
    └── 公共资料/
```

---

# 六、一节课一个目录

每节课建立一个独立目录：

```text
科目+课次_课程内容_YYYY-MM-DD_周X
```

例如：

```text
政治1_必修一第1-2课_2026-09-08_周二/
```

内部：

```text
政治1_必修一第1-2课_2026-09-08_周二/
├── 政治1_课堂录音转文字稿_必修一第1-2课_2026-09-08_周二.md
├── 政治1_课堂笔记_必修一第1-2课_2026-09-08_周二.md
├── 政治1_要背的东西_必修一第1-2课_2026-09-08_周二.md
├── 政治1_课后整理_必修一第1-2课_2026-09-08_周二.md
└── 政治1_错题_必修一第1-2课_2026-09-08_周二.md
```

文件夹信息不能代替文件名信息。

# 七、整个仓库的文件类型限制

## 1. 仓库定位

`Learning-Library` 是**结构化学习资料库**，不是原始媒体文件备份盘。

仓库中的资料应尽可能保持：

- 可搜索
- 可阅读
- 可被 AI 直接理解
- 可通过 Git 比较版本
- 文件体积小
- 长期易维护

因此优先保存文本类资料。

## 2. 推荐格式

优先：

```text
.md
.txt
```

其中整理后的学习资料原则上优先使用：

```text
.md
```

## 3. 禁止存放二进制大文件

整个仓库原则上禁止直接保存：

```text
图片：
.jpg .jpeg .png .webp .heic .gif 等

音频：
.mp3 .wav .m4a .aac .flac 等

视频：
.mp4 .mov .mkv .avi 等

压缩包：
.zip .rar .7z 等

其他不适合 Git 长期管理的大型二进制文件
```

## 4. 二进制资料的处理方式

如果用户提供：

- 课堂录音
- 错题截图
- 试卷照片
- 板书照片
- 课堂视频
- 老师展示的图片资料

这些原始二进制文件**不直接进入仓库**。

应根据任务需要提取其中有用的信息，转换成适合长期保存的 Markdown 或文本资料。

例如：

```text
课堂录音
↓
政治1_课堂录音转文字稿_必修一第1-2课_2026-09-08_周二.md
```

```text
错题截图
↓
整理进：
政治1_错题_必修一第1-2课_2026-09-08_周二.md
```

```text
老师板书照片
↓
政治1_老师板书转写_必修一第1-2课_2026-09-08_周二.md
```

## 5. 不得为了文本化而猜测

将图片、录音等内容转换为文字时：

- 看不清的不猜
- 听不清的不猜
- 公式不确定的不猜
- 题目缺失部分不猜
- 数字不确定的不猜

无法可靠确认时应明确标记，例如：

```text
【此处原始资料无法可靠识别】
```

---

# 八、用户要求直接存入仓库的文本文件保护

对于用户明确要求：

- 放进仓库
- 上传到仓库
- 保存到仓库
- 归档到仓库

且符合仓库文件类型要求的原始文本文件，默认不得擅自修改内容。

禁止：

```text
纠错
删减
补充
重排内容
改写
总结
重新组织
改变含义
```

允许：

1. 判断归属
2. 判断课次
3. 判断资料类型
4. 确认课程内容
5. 确认日期和星期
6. 按规范重命名
7. 原样保存

如果用户要求“整理后存入”，则整理结果作为新的文件保存，不应偷偷替换原始文本。

---

# 九、禁止擅自覆盖已有资料

已有文件默认不覆盖。

如果需要新增：

- 整理版
- 校正版
- 补充版
- 更新版

原则上新增或按用户明确要求修改。

只有用户明确要求：

```text
覆盖原文件
替换旧文件
直接修改这个文件
```

才允许覆盖。

---

# 十、仓库内资料必须互相关联使用

`Learning-Library` 中同一课程的资料不是彼此孤立的。

在生成、整理、分析新的学习资料时，应主动查看并利用仓库中相关已有资料，例如：

```text
课堂录音转文字稿
课堂笔记
要背的东西
课后整理
错题
老师课件转写
老师板书转写
前后课程相关内容
同知识点已有资料
```

例如整理政治1错题时，不应只根据错题本身写解析。

应优先结合：

```text
政治1_课堂笔记_...
政治1_要背的东西_...
政治1_课后整理_...
政治1_课堂录音转文字稿_...
```

如果该知识点在政治2、政治3中又被老师补充，也可以联系后续相关资料。

原则：

> **仓库中的资料应形成一个相互关联的学习体系，而不是互相独立的文件集合。**

---

# 十一、资料缺少信息时

不得凭空猜测。

按照以下顺序判断：

1. 当前文件内容
2. 同批次资料
3. 同一课堂已有文件
4. 仓库历史课程记录
5. 相关知识点的其他资料
6. 必要时查询 Google 日历

如果不知道课次，可以查询 Google 日历，根据该科目的历史上课日期和实际上课顺序推算。

推算时必须考虑：

- 取消课
- 补课
- 调课
- 重复日历事件

Google 日历时间按照**北京时间**处理。

仍无法可靠判断时，再向用户确认。

---

# 十二、完整执行原则

```text
1. 文件名：
   科目+课次_资料类型_课程内容_YYYY-MM-DD_周X.扩展名

2. 每个文件单独拿出来必须能判断：
   科目、课次、资料类型、课程内容、日期、星期。

3. 一节课一个目录。

4. 日期统一按北京时间，并标星期。

5. 仓库以 Markdown 和文本为主。

6. 图片、录音、视频、压缩包等二进制大文件不进入仓库。

7. 二进制资料中的有效内容应转写、提取或整理成文本后保存。

8. 转写和提取时不得猜测无法确认的内容。

9. 用户要求原样保存的文本文件不得擅自修改内容。

10. 可以按规范重命名文件。

11. 未经明确要求，不得擅自覆盖已有文件。

12. 新整理资料时应主动联系仓库中的相关已有资料。

13. 不知道课次时可以结合仓库记录和 Google 日历推算。

14. 无法可靠确认的信息不得猜测。
```
