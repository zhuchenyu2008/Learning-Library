# Learning-Library 自动入库规范

## 一、适用范围

本规范用于用户已经明确表达“需要将当前学习资料整理、保存、归档或写入 Learning-Library 仓库”的场景。

典型表达包括但不限于：

```text
按规范整理并入库
按规范放进去
放进仓库
保存到仓库
归档到仓库
整理好后入库
把这些资料按规则存进去
```

## 二、明确入库意图后直接执行

当用户当前请求已经明确包含入库意图时，视为已经获得本次任务所需的仓库写入授权。

此时必须直接执行，不得再要求用户重复回复：

```text
“按规范整理入库”
“确认入库”
“确认写入”
“请再回复一句……”
```

也不得仅因为需要遵守仓库规范，就把已经明确的写入请求再次变成二次确认流程。

原则：

> 用户当前请求已明确要求入库 = 直接按仓库规范执行，不再要求重复确认。

## 三、自动执行不等于无限写入权限

“直接执行”只覆盖当前任务明确涉及的资料和为完成当前任务直接需要修改的规则文件。

默认仍然禁止：

- 修改用户当前任务未提到的其他学习资料
- 覆盖无关已有文件
- 删除无关文件
- 重命名、移动无关文件
- 改变无关目录结构
- 对整个仓库进行顺手清理或重构

读取其他文件用于判断课次、关联知识、避免重复是允许的，但读取不等于获得修改权限。

## 四、资料信息不完整时的处理

若科目、课次、课程日期、课程内容等信息没有直接写明，应先按《存储规范》规定的顺序自动判断：

1. 当前资料
2. 同批次资料
3. 同一课堂已有文件
4. 仓库历史记录
5. 相关知识点资料
6. 必要时查询 Google 日历

能可靠判断时直接执行，不要为了形式上的确认而询问用户。

只有在关键信息确实无法可靠确认，且继续写入可能导致错误归档、错误覆盖或课次明显错误时，才向用户询问缺失信息。

## 五、覆盖与冲突仍需遵守原规则

若目标路径已经存在文件，而用户没有明确要求覆盖、替换或直接修改，则不得覆盖。

应优先：

- 新增整理版
- 新增补充版
- 新增校正版
- 或根据现有规范进行追加

涉及同课次“必背”“错题”等已有文件时，按对应专项规则执行。

## 六、仅上传文件不等于自动入库

用户只是上传文件、粘贴资料、发图片或发录音，但没有表达保存、整理入库等意图时，不得仅凭文件出现就擅自写入 GitHub。

只有当前请求或上下文已经明确要求将这些资料入库时，才能自动执行。

## 七、用户明确禁止入库时

如果用户明确说：

```text
不要入库
只在聊天里整理
先别写仓库
暂时不要保存
```

则不得写入仓库，即使之前存在自动入库习惯。

## 八、核心规则

```text
1. 当前请求已明确要求入库时，直接执行，不再要求用户重复确认。
2. 不再要求用户专门回复“按规范整理入库”才能继续。
3. 能通过资料、仓库或日历可靠判断的信息，应自动判断后执行。
4. 真正无法可靠判断关键归档信息时，才询问用户。
5. 自动入库权限仅限当前任务相关文件，不扩展到无关仓库内容。
6. 已有文件仍按“禁止擅自覆盖”规则处理。
7. 仅上传资料但未表达入库意图时，不自动写入。
8. 用户明确说不要入库时，立即停止自动入库。
```
